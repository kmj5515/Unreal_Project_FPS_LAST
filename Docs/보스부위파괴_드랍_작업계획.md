# 보스 부위 파괴 · 사망 드랍 — 작업 계획 (3라운드 비평 반영 최종본)

> 3인 병렬 비평 × 3라운드 + 메인 세션 코드 재검증을 거쳐 확정. 각 항목은 실제 코드 근거 기반.
> 스코프 전제: 아웃게임 Economy/Quest/Loadout이 **로컬 GameInstanceSubsystem(무복제)** → 솔로/리슨서버 기준. 데디서버는 별도 표기.
> **인게임은 리슨서버 원격 클라를 실재 타깃**(PlayerState ASC/킬피드/Multicast 히트사운드 등 MP 스캐폴딩 존재) → 인게임 복제/서버권위는 진짜 요구사항.

## 핵심 사실 (코드 확인)
- 데미지 = 서버 라인트레이스(`WeaponComponent.cpp:439`, ByObjectType) → `LastFPSDamage::CalculateDamage`(소스 ASC만) → `SetByCaller_Damage` → `HandleDamageEffect`가 소비. 4개 진입부가 단일 헬퍼 `RollAndApplySetByCallerDamage`(`LastFPSDamageCalculation.cpp:119`)로 수렴.
- `Defense` 어트리뷰트 존재·**복제 등록됨**(`LastFPSAttributeSet.cpp:66` `DOREPLIFETIME_CONDITION_NOTIFY`, `OnRep_Defense` `:213`). 단 전투 **미사용**(관통/약점/방어감소 공식 없음). ← 복제 여부 우려는 종결.
- 적 사망 = `HandleDamageEffect`의 `NewHealth<=0` 분기(서버권위 게이트). 별도 이벤트/래치 없음. 콜리전 비활성은 `OnHealthChanged→UpdateAliveCollisionState`(서버·클라 공통).
- **적 BP에 StatData/CharacterDefinition 없음** → 현재 모든 적 HP는 `MaxHealthOverride=10000`에 의존. 끄면 생성자 기본 100으로 붕괴.
- 무기 게임플레이 스탯 = FireRate, DamageRange만. Penetration/Weakpoint/BreakPower는 **표시 전용**(전투 미연동).
- `GE_HealInstant`(+35 고정), `AWeaponPickupActor`(Hero 직접 장착), Economy `AddItem/AddCredits`. HP픽업·일반아이템픽업·드랍시스템 전무.

## Phase 0 — 선행 (0.1·0.3 = 공통 / **0.2 = 보스 전용**)
> **[3R]** 0.1(HP 데이터화)·0.3(사망훅/래치)은 보스·드랍 공통 토대. **0.2(ExecCalc)는 보스에만 필요** → 드랍보다 뒤, 보스와 동반.

### 0.1 적 HP 데이터화 [P0, 필수]
- 기존 적 BP(BP_EnemyBase 등) **StatData 부재 확인됨** → 적 유형별 StatData(DA) 생성, 기존 10000 값 이관.
- `bUseDataDrivenHealth` **단일 bool**(기본 `false` = 기존 override 유지, 점진 전환). `true`면 `PossessedBy`에서 `SetMaxHealth/SetHealth` override 스킵 → Super의 StatData/GE 값 신뢰.
- 데이터 소스 null인데 `true`면 **Error 로그 + 안전 폴백**(조용한 100 붕괴 방지). `MaxHealthOverride` 매직값 10000 제거.
- 보스 HP도 `SetHealth` 직접 호출 금지 → StatData/`ApplyToAbilitySystem` 경로로 주입.
- 근거: r2-c1, r2-c7, r1-c5.

### 0.2 데미지 파이프라인 → ExecutionCalculation **하이브리드** 이관 [보스 전용 선행 · 드랍과 무관]
> **[3R 수정] 드랍의 공통 선행에서 제외.** 드랍은 데미지 수치 계산이 전혀 필요 없음(사망훅+AddItem뿐) → 0.2는 **2.x 보스 착수와 동반**. 착수 순서 참조.
- `UGameplayEffectExecutionCalculation` 신설(소스+타깃 어트리뷰트 Capture). **하이브리드 형태**: **소스측 roll/AttackDamage/원소배수/크리는 기존 `CalculateDamage`(SetByCaller)로 유지**, ExecCalc는 **타깃 `Defense`/armor/약점배수 capture + 후보정만**. (GASShooter 표준형 = SetByCaller_Damage를 base로 캡처 → ExecCalc에서 타깃 armor 감쇄)
  - **전면이관 폐기 근거**: roll/원소/크리는 전부 소스측이라 현 함수로 이미 정확. 전면이관은 크리 플래그(`SetByCaller_CriticalHit`, `HandleDamageEffect`가 `LastFPSAttributeSet.cpp:135`에서 소비) 전파를 복잡하게 만들어 **정석상 손해**.
  - **크리 신호 운반**: `ExecCalc::Execute`의 소유 스펙은 const라 SetByCaller **재기록 취약** → 크리는 호출부에서 계속 세팅(하이브리드면 자연 해결). 굳이 ExecCalc 경유해야 하면 **전용 크리 meta-attribute(캡처/출력) 또는 적용 스펙 dynamic GameplayTag**로.
- **GE 클래스 교체(4곳)와 계산 로직 이관은 별개**: 방어/밸런스 불일치를 막으려면 armor-aware GE로의 **GE 교체는 4개 호출부 동시 필요**(`WeaponComponent.cpp:486`, `LastFPSProjectile.cpp:183`, `LastFPSProjectileImpactRule.cpp:71`, `LastFPSAreaEffectActor.cpp:211`). 그러나 **계산 로직 전면이관은 불필요**(위).
- 타깃 `Defense` capture → 방어감소식. **부위 armor/약점/관통은 2.1 완료 후 활성**; 그전엔 `BoneName=None→배수 1.0` 폴백 + 개발빌드 경고 로그.
- '함수 확장' 방식은 타깃 ASC 접근 불가라 **폐기**(`CalculateDamage`가 소스 ASC만 캡처 `LastFPSDamageCalculation.cpp:54`).
- 근거: r1-c2, r2-c3, r2-c4, r2-c5, **r3(하이브리드/크리)**.

### 0.3 사망 훅 통합 + 래치 [필수]
- `HandleDamageEffect` 사망 분기(서버권위 게이트 안)에서 `TargetChar->HandleDeath()` **1회** 호출. (그린필드 아님 — 기존 경로 통합)
- `ALastFPSCharacterBase`에 `bHasDied` **서버권위 래치** + `OnDeath` 델리게이트. `HandleDeath`는 `HasAuthority && !bHasDied`일 때만. `HandleDeath`는 **서버 래치 + 원샷 사망로직(드랍 브로드캐스트 등)만** 소유.
- **[3R 수정 — 실버그 방지] 클라 콜리전 경로를 걷어내지 말 것.** 현재 클라 콜리전 비활성은 Health 복제 → `OnHealthChanged` → `UpdateAliveCollisionState`(`LastFPSCharacterBase.cpp:346`)로 **모든 원격 클라에서 이미 동작 중**. 이 경로를 "클라 시각화 전용"으로 축소·제거하면 **모든 원격 클라가 시체와 계속 충돌하는 라이브 회귀** 발생(접속 시점 무관). → 콜리전은 복제 Health/OnHealthChanged 경로에 **그대로 유지**.
- (선택) 사망 애님/시각 패리티가 필요하면 `bHasDied`를 **복제 프로퍼티 + `OnRep_bHasDied`**로 추가. **부활 미지원 확정**(권장).
- 근거: r1-c4, r2-c9, **r3(콜리전 회귀)**.

## Phase 1 — 사망 드랍 (Phase 0 위)

### 1.1 드랍 책임 분리
- 적 전용 **`UDropComponent`(무복제)** 또는 GameMode가 `OnDeath` 구독 → 드랍 롤/스폰/지급. `HandleDeath`는 래치+브로드캐스트만(월드 스폰 금지).
- **[3R 수정] 컴포넌트는 복제하지 않음.** 복제 기준 = "원격 클라가 렌더에 이 상태를 읽어야 하는가?" → DropComponent는 **서버측 롤/스폰 로직 홀더**일 뿐 클라가 읽을 상태 0 → **무복제.** 복제되는 건 **스폰된 픽업 액터 자체**(`bReplicates`, 자체 복제). 최소 정석: 서버 훅 롤 → 서버가 자체복제 픽업 액터 스폰 → Hero 오버랩(서버 게이트+`Cast<ALastFPSHero>` 필터) → `AddItem`.
- 근거: r2-c15, **r3(복제 대상=스폰액터)**.

### 1.2 DT_DropTable [스키마 즉시 동결]
- 행: `{ HpDropChance: float(0~1), Items:[{ ItemRowId:FName, Chance:float(0~1), CountMin:int, CountMax:int }] }`. 확정 드랍 = `HpDropChance=1.0`.
- 서버 사망 훅(래치됨) 안에서 `FRandRange(0,1) < Chance` **1회** 롤(클라 공용 경로로 새지 않게). 근거: r2-c16(스키마), r1-c9.

### 1.3 아이템 지급
- **반드시 `EconomySubsystem.AddItem` 경유**(HasItemDefinition 게이트 = 유령아이템 차단).
- 스코프: **솔로/리슨서버 OK. 데디서버는 클라 전파 안 됨(미지원)** — 지급부에 제약 주석 명시. MP 확장 시 서버 스폰 복제 픽업+오너 Client RPC 또는 인벤토리 PlayerState 승격 필요.
- `DT_DropTable`을 `EconomySubsystem::ValidateReferences`에 편입(Shop 검증 패턴, 시작 시 유령참조 Error). 근거: r1-c1, r1-c10, r2-c6.

### 1.4 HP 픽업
- (선택) `APickupActorBase` 추출(스피어/프로파일/오버랩 바인딩/HasAuthority 게이트/가상 `OnPickedUp`) → `AWeaponPickupActor`·`AHealthPickupActor`가 상속. 안 하면 사실상 복붙. 근거: r2-c14.
- 오버랩: **서버 게이트 + `Cast<ALastFPSHero>` 필터**(적이 힐 줍는 것 방지). 근거: r2-c13.
- 힐 적용: 대상 ASC에 GE(`MakeOutgoingSpec`+`ApplyGameplayEffectSpecToSelf`). **WeaponPickup 상속 금지**(그건 Hero 직접 장착 경로).
- 회복량 데이터화하려면 `SetByCaller_Heal` 태그 신설 + `GE_HealInstant` modifier를 SetByCaller로 개조(선행). **공수 절감하려면 고정 35 유지도 가능.** 근거: r1-c8, r2-c11.

## Phase 2 — 보스 부위 파괴 (Phase 0 위)

### 2.1 부위 트레이스 [선행 필수]
- 현 1차 발사 트레이스는 **캡슐(ObjectType=Pawn)이 먼저 맞아 BoneName=None**. "BoneName 재사용, 히트박스 불필요" 전제 폐기.
- **'전용 채널(캡슐 Ignore)' 방식 폐기** — 발사부가 `ByObjectType`라 채널 응답 무시(비호환). 발사부 손대면 전 무기 회귀 위험.
- 방식 확정: 1차 트레이스로 명중 액터 확정 → 보스면 **보스 메시 한정 2차 `LineTraceSingleByChannel`/`ComponentLineTraceSingle`(캡슐 무시)** 로 BoneName 획득.
- 보스 **PhysicsAsset을 목표 부위(머리/팔/코어)로 세분화 필수**. 디버그로 BoneName 채워짐 검증. None/미매핑 → 배수 1.0 폴백. BoneName을 `Context.AddHitResult`로 ExecCalc 전달. 근거: r1-c3, r2-c2.

### 2.2 부위 armor/약점배수
- ExecCalc(0.2)가 **부위 키 → 부위 DataAsset** 조회 → 방어감소 + 약점배수 + 관통 상쇄.
- **[3R 수정] 조회 키는 raw `FName BoneName` 금지.** 리그 본 리네임 시 조용히 깨짐 → **GameplayTag(bone→tag 맵) 또는 PhysicalMaterial**로 키잉(리네임 강건). 근거: r1-c6, r1-c7, **r3(키 취약성)**.

### 2.3 부위 내구도 저장/차감
- **저장소 분리 수용**: ExecCalc는 HP 데미지 산출만. 부위 내구도는 **`BreakablePartsComponent`(복제)** 에 저장.
- **[3R 확정] BreakableParts는 처음부터 복제로 착수**(드랍의 무복제와 반대 — 혼동 금지). 크랙/발광/파괴 메시는 **세컨드 플레이어가 봐야 정합** → 클라 관측 상태. 비용 비대칭: 지금 복제 = `TArray<부위내구>` + `DOREPLIFETIME` + `OnRep` 하나(솔로에선 원격 클라 없어 inert, 다운사이드 0) vs 나중 전환 = write 경로 전체를 `HasAuthority` 뒤로 재배치 + MID 갱신을 OnRep으로 이동(핵심 데이터플로 재작성). **서버권위 write + OnRep 시각화**로 착수. (부위 수 적으면 단일 OnRep 충분, 스케일 시 `FFastArraySerializer`.)
- 차감: `HandleDamageEffect` 후처리(서버 게이트)에서 `Context HitResult.BoneName`으로 부위 조회 → 내구도 차감. 분배규칙 = 데이터 튜닝 항목(스키마 블로커 아님). 근거: r2-c8.

### 2.4 파괴 연출/복제
- **[3R 수정] durable "파괴됨" 상태 ≠ 일회성 이벤트.** 부위 내구도 배열 **복제** OnRep이 **지속 크랙/발광(부위별 MID 스칼라)뿐 아니라 "완전 파괴 메시 스왑"까지 재구성**해야 함(late-join 정합). Multicast RPC는 **파괴 순간 접속해 있던 클라에만 전달** → 보스전 도중 접속(순수 late-join)에 누락되므로 durable 메시 스왑을 얹으면 안 됨.
- **Multicast + GameplayEvent는 순간 버스트(VFX/임펄스/경직)에만** 한정. (구현은 co-op/MP 폴리시로 유예 가능하나 "durable=복제배열 OnRep / Multicast=순간" **설계 전제는 지금 못박음** — 나중에 Multicast에 durable을 얹어놓고 뜯는 게 비쌈.)
- 파괴 시 armor 감소·경직. 근거: r2-c12, **r3(late-join durable 상태)**.

## 권장 착수 순서
**[3R 수정] 0.1(마무리) → 0.3(사망훅/래치, 콜리전 보전) → (1.x 드랍) → [0.2 ExecCalc + 2.x 보스 동반]**
- 0.1(HP 데이터화)·0.3(사망훅)만 보스·드랍 공통 토대. 0.1을 안 하면 보스 HP가 10000 매직값에 묶임.
- **0.2(ExecCalc)를 공통 선행에서 제외**: 드랍은 데미지 수치 계산 무관(사망훅+AddItem뿐) → 0.2는 보스 방어/부위가 실제로 필요한 **2.x 착수 시점에 동반**. 전면이관이 아니라 하이브리드라 이관 비용도 축소.
- 0.1은 이미 미커밋으로 진행 중(`LastFPSEnemyCharacter.h`). 드랍(1.x)이 보스(2.x)보다 공수 작고 독립적이라 먼저 가시 성과 확보.

## 기각/보류
- r2-c10 (Defense 미복제): **완전 종결.** 메인 세션 직접 확인 — `Defense`는 `LastFPSAttributeSet.cpp:66`에 `DOREPLIFETIME_CONDITION_NOTIFY`로 등록됨(`OnRep_Defense` `:213`). 클라 UI/예측이 읽어도 안전. 추가 확인 불필요.

## 추가 제안 — 레벨/경험치 (공수 평가)
**결론: 가성비 높음. Phase 0 이후 얹으면 공수 적음.**
- 킬 감지가 **이미 사망 경로에 존재**(`Auth_AddDeath`), 0.3의 `OnDeath` 훅을 그대로 재사용 → "적 사망 시 킬러에게 XP" 통합 지점이 공짜로 생김.
- XP/Level 상태는 Economy와 **동일한 로컬 서브시스템 패턴**(GameInstanceSubsystem)으로 미러 → 신규 인프라 최소.
- 레벨업 보상(스탯 증가)은 0.1에서 손대는 **StatData/GAS 경로 재사용**(MaxHealth/AttackDamage 등 상향), 알림은 기존 `ShowNotice` 재사용.
- 추가 실작업: XP 커브 데이터(Curve/DataTable) + 레벨업 스탯 적용 + 약간의 UI.
- 스코프 주의: Economy와 동일하게 로컬(무복제) → 솔로/데모엔 충분, MP는 별도.
- **추천 시점**: Phase 0 완료 직후(OnDeath + StatData가 준비된 시점)에 삽입하면 최소 공수.
